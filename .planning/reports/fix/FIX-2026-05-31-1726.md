# Fix Report - 2026-05-31 17:26

**Symptom:** On the Dubai Shop (`/shop`), every fragrance appears multiple times (at least 3x depending on size). Example reported: "Imagination by Louis Vuitton (10 ml)". Size selection was supposed to live only on the individual product page, not on the listing grid.
**Mode:** frontend
**Outcome:** fixed

## Feedback Loop
- Initial failing check: code inspection — three listing routes feed raw size-variant rows into `ProductGrid`, which renders one card per row (no dedup).
- Final passing check: `npx jest src/lib/supabase/__tests__/collapse-variants.test.ts` (5/5 pass) + `npx tsc --noEmit` (exit 0).

## Root Cause
`src/app/shop/page.tsx:28` (and `src/app/shop/[category]/page.tsx:62`, `src/app/shop/lattafa/page.tsx:35`) — the `products` table is a *variant* table: 50ml / 100ml perfume, 10ml oil, and 150ml lotion are separate rows sharing a base slug (documented at `src/lib/supabase/product-service.ts:109-130`). The listing routes filtered by `product_type` but never collapsed those size-variant rows, so the grid (`src/components/storefront/ProductGrid.tsx:413`) rendered the same fragrance two-to-four times. The symptom follows directly: "Imagination" has a 50ml + 100ml perfume row (and oil/lotion siblings), each becoming its own card. The contract — size chosen on the product page only — was never enforced on the grid.

## Patch
- Files changed:
  - `src/lib/supabase/product-service.ts` — added exported pure helper `collapseToFragranceCards(products)`: groups rows by `getVariantBaseId`, keeps one representative per base id (lowest variant sort key → 50ml perfume preferred, then 100ml, oil, lotion), preserves first-seen order so the caller's in_stock/created_at ordering still drives the grid.
  - `src/app/shop/page.tsx` — wrap the perfume filter in `collapseToFragranceCards`.
  - `src/app/shop/[category]/page.tsx` — same.
  - `src/app/shop/lattafa/page.tsx` — collapse all Lattafa rows (this route had no `product_type` filter, so it showed up to 4 cards per fragrance).
  - `src/lib/supabase/__tests__/collapse-variants.test.ts` — new unit test pinning the dedup contract.
- Scope note: widened from the default 3-file budget to 4 source files. The reported symptom and the agreed "size only on the product page" contract apply identically to all three listing routes; the change is a one-line application of a single shared helper, not three independent fixes. The shared data fetchers (`getAllProducts`, `getProductsByCategory`) and the PDP variant logic (`getProductVariantGroup`) are untouched, so the product page still surfaces every size.
